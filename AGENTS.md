# Copilot Instructions for Faraway-Ash

## Project Overview

This is a personal blog site "遥尘" (enita.cn) built with **Zola** (a Rust static site generator). The frontend theme is custom-built (95% AI-free, per README) using TypeScript, Tailwind CSS v4, and Rolldown.

## Architecture

- **`src/`** — Zola site root. Contains content (`content/`), templates (`templates/`), and static assets (`static/`).
  - `src/zola.toml` — Zola configuration
  - `src/templates/` — Tera (Django-style) HTML templates
  - `src/content/` — Blog posts as Markdown files
  - `src/static/` — Compiled JS/CSS output and other static resources (such as images)
- **`frontend/`** — Frontend source code (TypeScript + CSS), compiled into `src/static/`
  - `frontend/src/main.ts` — Entry point, imports all sub-modules and initializes lucide icons
  - `frontend/src/dark-mode-switch.ts` — Custom dark mode (system/dark/light cycling via localStorage)
  - `frontend/src/content.ts` — Article page features (heading anchors, GLightbox, TOC sidebar, anchor highlight)
  - `frontend/src/search.ts` — Client-side search using Zola's Fuse.js JSON search index
  - `frontend/src/overlay-scrollbars.ts` — Custom scrollbar initialization
  - `frontend/src/utils.ts` — Utility functions (`cn()`, `toast()`)
  - `frontend/css/main.css` — Tailwind CSS v4 entry point with custom theme, fonts, and OverlayScrollbars styling

## Key Commands

```bash
# Install dependencies
pnpm install

# Dev mode (needs tmux): watches JS bundling + CSS rebuilding
pnpm dev

# Production build: bundles JS and CSS
pnpm frontend-build

# Lint and format (JS/TS/CSS via Biome)
pnpm biome check --fix

# Format only
pnpm biome format --fix

# Format HTML/Tera templates (uses djhtml, a Django template formatter)
pip install -U djhtml
djhtml path/to/template.html

# Zola dev server (live-reloads site)
zola -r src/ serve

# Zola production build
zola -r src/ build
```

## Key Conventions

### Templates (Tera/HTML)
- Templates use the Tera engine (Django/Jinja2-like syntax: `{% %}`, `{{ }}`)
- All pages extend `base.html` via `{% extends "base.html" %}`
- Content blocks go inside `{% block content %}{% endblock content %}`
- Template files live in `src/templates/`

### CSS & Design System
- Uses **Tailwind CSS v4** with `@import "tailwindcss"` (not v3 config-file approach)
- Uses Tailwind CLI to produce a single CSS file at `src/static/app.css` (no Rolldown integration)
  - Compiled CSS artifact should NOT be committed into version tree; the CI compiles it on the go.
  - Except for `giallo-dark.css` and `giallo-light.css`. They are static resources for code highlighting, and would not be changed throughout the versions.
- Custom CSS variables define a design token system in `main.css`:
  - `--background`, `--foreground`, `--muted`, `--muted-foreground`, `--border`, `--ring`, `--strong-accent`, `--soft-foreground`
- Dark mode uses a `.dark` class on `<body>`, toggled by custom JS (not Tailwind's `prefers-color-scheme`)
- Custom utility classes use the `fa-` prefix (e.g., `fa-container`)
- Icon variants use lucide's `data-lucide` attribute with `createIcons()` from the `lucide` package
- Icons are explicitly imported in `main.ts` — never use the full `lucide` import


### TypeScript / Frontend
- Entry point: `frontend/src/main.ts` — compiles via Rolldown to `src/static/app.js` as a single ESM bundle
  - Compiled JavaScript artifact should NOT be committed into version tree; the CI compiles it on the go
- TypeScript source is in `frontend/src/`, no `tsconfig.json` (Rolldown handles TS)
- Uses `clsx` + `tailwind-merge` for composable class names (`cn()` utility)
- Custom scrollbars via OverlayScrollbars with `os-theme-custom` theme class
- Custom HTML elements: `<fa-toc-header>`, `<fa-toc-children>` for table of contents sidebar
- GLightbox is used for image lightbox on article pages


### Content / Blog Posts
- Written in Markdown in `src/content/`
- Frontmatter (TOML format) can include: `title`, `date`, `description`, `tags`, `categories`, `authors`
- Content pages use `page.html` template (with banner, TOC, tags, share button)
- Search index is auto-generated by Zola using `build_search_index = true` and `index_format = "fuse_json"`

### Tooling
- **Package manager**: pnpm (v10.27.0) — NEVER use npm/yarn
- **JS bundler**: Rolldown (config: `rolldown.config.ts`)
- **Linter/Formatter**: Biome v2 (config: `biome.json`) — covers `frontend/**/*.js`, `frontend/**/*.ts`, `frontend/**/*.css`
- **Formatter for templates**: djhtml (pip package)
- **Version cache-busting**: `config.extra.version` in `zola.toml` is appended to JS/CSS URLs as `?version=N`
- Both VS Code (`.vscode/settings.json`) and Zed (`.zed/settings.json`) have project settings committed

### Deployment (CI)
- GitHub Actions workflow in `.github/workflows/main.yml`
- Triggered on push to `main` branch
- Builds frontend (pnpm) → builds Zola site → deploys to server via SSH (rsync) and to Cloudflare Pages (force-pushes to `cf_web` branch)
- Two builds happen: one for the main server, one for Cloudflare Pages (with modified `base_url` in `zola.toml`)
